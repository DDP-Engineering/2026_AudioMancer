## Design

- REQ-FUNC-151a9e10: expose `plan_question_batches(questions, profile_payload)` from adjudication as the public plan seam; it normalizes questions, rejects unusable profiles with an empty plan, groups by sorted type, preserves within-type input order, and applies the existing 4/8/16 tier.
- REQ-FUNC-151a9e10: checkpoint creation/reset persist target IDs projected from those planned batches, while runtime enumerates the same batch objects into stable `cleanup-batch-NNNN` IDs; recursive child splits never replace the persisted top-level plan.
- REQ-UX-bb78f412: `clean_text` passes durable `progress.completed_request_count` into adjudication; answer records remain solely the pass-skip mechanism, and runtime total expansion is persisted before cancellation can interrupt progress.
- REQ-UX-bb78f412: progress emitters preserve completed work by expanding total to at least current instead of clamping current; the existing 8-88 AI band and terminal 94/98/100 transitions remain unchanged.
- REQ-REL-a6bddb67: the strict Cleanup validator gains complete boundary-shape validation and wraps nested validator shape failures as `CleanupDocumentError`; `_can_reuse_analysis` calls it before status, progress, policy, question, reset, or answer access.
- REQ-REL-a6bddb67: any failed reuse validation returns false and follows the existing fresh-analysis checkpoint/cancellation path without salvage; valid running, paused, finalizing, and completed documents follow their current recovery branches.
- Test seams: adjudication tests compare public plan and actual request IDs/membership across mixed types and tiers; quality-contract run tests cover multi-question cancellation/resume, verifier states, split expansion, malformed nested checkpoints, strict loader behavior, and reusable lifecycle states.
- Rejected alternative: reconstructing completed requests from per-question answers cannot distinguish one multi-question request from many and cannot recover dynamic split totals, while importing orchestration into adjudication would create a service cycle.
- Expected implementation files: both Cleanup services and tests, plus `cleanup_analysis_service.py` only for the boundary-owned validator; delivery updates the three requirements, shared spec, Text Cleanup knowledge, changelog, guides only if user-facing recovery text changes, and this journal.
