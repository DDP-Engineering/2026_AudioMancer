## Design

**Approach**
- OBSERVED: the native LM Studio listing separates maximum and loaded context; Ollama /api/show and /api/ps serve those respective values. Query metadata only on the existing connection probe.
- Preserve the configured budget as an operator setting and clamp the planning value with exact-model advertised and loaded values where known. Unknown loaded context keeps a local configured budget; reconnect after server changes.
- Apply the online fraction as an additional ceiling after reserving context, keeping current workflow-specific fractions. Use effective context in the Cleanup checkpoint fingerprint and in Book Analysis UI/worker gating.
- Send the configured output limit via Chat Completions and use the smaller calculated per-request limit for Cleanup and Book Analysis. Keep the limit across retries and JSON repair.

**Interfaces and data**
- Probe returns optional server_context_window with its existing exact model owner. Persist it alongside the discovered context for the same selected model. Clear runtime context when editing the endpoint, model or backend. A prior model maximum on the same server stays scoped to its owning model. Failed connection probes retain prior success metadata.
- AI Settings summarizes model, server and effective context. It labels the cap on Chat Completions profiles and the local reserve on the separate ChatGPT Subscription transport.
- Start with max_tokens. On explicit dialect rejection, switch once to max_completion_tokens with the same value. No request loses the cap through negotiation.

**Files and test seams**
- Backend discovery, profile UI and settings for REQ-FUNC-b71d046c, REQ-UX-3aba716c, REQ-FUNC-20817a63 and REQ-FUNC-6f8e52c8.
- Shared budget, Character Discovery synthesis, Cleanup and Book Analysis for REQ-FUNC-c5162d09, REQ-FUNC-2ed75319 and REQ-FUNC-21601fff.
- Provider wire tests and workflow reservation tests for REQ-PLAT-75d29093, REQ-NFR-414888ee, REQ-FUNC-644ff463, REQ-FUNC-91e20a10, REQ-FUNC-18168ed4 and REQ-REL-484a0674. Localized editor test for REQ-UX-34b436ff.

**Risks and open decisions**
- UNKNOWN: private subscription endpoint acceptance of max_output_tokens. Its existing separate Responses request shape remains the baseline.
- OBSERVED: server identity can change between probes. Display is last successful probe, with a manual Connect refresh. Backend IDs can alias variants or multiple loaded instances; prefer an exact instance and use the model's sole unambiguous instance otherwise.
- STATED: focused tests only. Use synthetic EN/RO prompts on authorized LAN backend, one test-loaded instance at a time.
