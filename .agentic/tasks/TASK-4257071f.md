## Design

- Components: TTS Settings page persistence and VoiceWeaver generated-WAV request handling (`REQ-FUNC-77fce48b`, `REQ-FUNC-8749869e`, `REQ-FUNC-6606ebfa`).
- Interface: preserve all public method signatures and persisted field names; add only a private page session marker and two narrow exception arms (`REQ-FUNC-77fce48b`, `REQ-FUNC-8749869e`, `REQ-FUNC-6606ebfa`).
- Data: `load_state` starts a new non-authoritative display session, `apply_probe_result` makes that session authoritative, and `build_settings` overwrites only the two probe fields when authoritative; discovered-model, active-model, and diagnostic cache behavior remains unchanged (`REQ-FUNC-77fce48b`, `REQ-FUNC-8749869e`).
- Error contract: both generated-WAV helpers translate only a direct `TimeoutError` to the existing exact request-timeout message with explicit chaining; HTTPError and URLError precedence stays unchanged (`REQ-FUNC-6606ebfa`).
- Rejected alternative: a shared request-error abstraction would broaden all request handling and risk changing the stable URLError contract, so this batch keeps the two explicit translations (`REQ-FUNC-6606ebfa`).
- Test seams: real page `load_state`/`apply_probe_result`/`build_settings`, main-window TTS controller save flow, and monkeypatched `_read_bytes` for both download helpers (`REQ-FUNC-77fce48b`, `REQ-FUNC-8749869e`, `REQ-FUNC-6606ebfa`).
- Expected files: both source modules, `test_tts_settings_page.py`, `test_main_window_lifecycle.py`, `test_voiceweaver_runtime_service.py`, three requirements, this journal, `TTS_Audio_Blocks.md`, and `CHANGELOG.md`.
