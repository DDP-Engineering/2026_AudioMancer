## Design

### Approach
INFERRED: Move deterministic analysis, rendering and text helpers into cleanup/; retain plain dictionaries and existing function APIs (REQ-NFR-5940b263).
INFERRED: Defer invalidation and publish through a Cleanup-owned staged replacement with relative-path backups and rollback (REQ-REL-8421d5d4).
INFERRED: A completed result keeps cleanup.json; only its replacement run uses cleanup_pending.json. First-run checkpoints remain cleanup.json. Successful publication removes pending data.
### Interfaces and data
INFERRED: clean_text gains force=False; confirmed UI reruns pass force=True without pre-reset. Pending runs resume without repeating the destructive confirmation.
INFERRED: Native/blank boundaries and protected roles precede page heuristics; hyphen rules apply across page-artifact bridges (REQ-FUNC-5f6bace8).
INFERRED: TXT verse uses locator.leading_spaces; renderer walks ordered spans/boundaries once for paragraph metadata (REQ-FUNC-d3d0f343, REQ-NFR-5940b263).
INFERRED: Exact unique unchanged paragraphs retain metadata after lexical edits; modified/duplicate content remains user_edited and unresolved (REQ-FUNC-9883c613).
INFERRED: Cancellation is checked at resume, during rendering and before publication; interrupted decisions remain resumable (REQ-REL-ab1ad6e4).
### Files and test seams
INFERRED: cleanup/{analysis,render,text,editing}.py owns pure processing; services/text_cleanup_service.py owns runtime coordination; cleanup_publication_service.py owns IO transactions.
INFERRED: Shared cleanup_text_analysis_service remains an explicit application facade for other workflow callers. Cleanup core imports no services.
INFERRED: config.py and operation_runtime_service.py register the pending artifact; UI controller defers reset; focused Cleanup, Chunking, new-format, UI, and artifact-reset tests cover integration.
INFERRED: Both user guides, changelog and Text Cleanup knowledge are updated; package version stays unchanged because no release was requested.
### Risks and open decisions
OBSERVED: Existing single-metadata and lexical-edit requirements need deliberate refinement, authorized by accepted proposals; no migration support is introduced.
INFERRED: Rollback covers handled IO exceptions; interrupted OS/process recovery retains named backups for inspection. No generic transaction framework.
UNKNOWN: Live model output quality; tests inject model responses and perform no paid inference.
