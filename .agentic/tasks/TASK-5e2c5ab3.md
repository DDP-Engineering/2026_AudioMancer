## Frame

Problem: Observed: Chunking mixes algorithms, provider calls, persistence and manual edits; regeneration removes prior results early and grouped metadata can misrepresent source roles.
Desired outcome: Stated: implement the accepted analysis as a clean isolated Chunking flow with recoverable publication and honest source provenance.
Actors: Operator using deterministic/AI Chunking and manual chunk editing.
Primary scenario: Chunk cleaned paragraphs, inspect/edit stable chunks, cancel/resume or regenerate without losing published downstream work on failure.
Examples: Heading plus body requested as one AI range becomes separate structural chunks; an over-budget paragraph is retained whole without an AI call.
Counterexamples: Source text is never generated by AI; a failed replacement must not erase a published translation or audio file.
In scope: Pure core, linear window cursor, structural roles and weakest confidence, source ranges/coverage, checkpoint identity, pending replacements, recoverable selective edits, EN/RO guides.
Out of scope: TTS-size splitting, new extraction formats, parallel model calls, provider redesign, migrations, packaging, commit.
Constraints: Stated: current branch, AEGIS autopilot, relevant tests only. Observed: existing stable IDs and selective impact policy must remain.
Success signals: Focused offline regressions prove roles/coverage/budget, resume and rollback; UI regeneration no longer pre-resets; both guides describe the resulting flow.
Evidence: Source and tests in deterministic_chunking_service, ai_chunking_service, chunking_document_service, text_chunking_state_service and text_chunking_ui_controller; read-only analysis probes reproduced page_artifact rejection and quadratic suffix planning.
Assumptions: Inferred: one operation owns project mutation at a time; recoverability covers caught publication errors, not power loss atomicity.
Unknowns: None blocking; implementation will exercise IO-failure recovery explicitly.
Decision-blocking questions: None; user accepted implementation and autopilot.
Proposed behaviors: Preserve source-only text, structural boundaries and stable IDs; recover prior files on publication errors; resume validated prefixes with explicit policy changes; disclose oversized fallback.

## Design

### Approach
REQ-NFR-6df93f95: pure chunking/{document,materialization,planning,descriptors}.py; services own source loading, calls, progress and persistence. AI adapter owns prompt/schema/provider handling. Keep existing facade APIs where consumers use them.
REQ-FUNC-6a9a707e / REQ-DATA-20f1afcf: split every accepted range at role transitions, standalone heading/page_artifact and omitted separators; merge flags and weakest confidence.
REQ-NFR-149f8458 / REQ-FUNC-16bd24d0: precompute paragraph costs once; select only the next window. Oversized first paragraph bypasses provider, remains whole and records a fallback warning.
### Interfaces and data
REQ-FUNC-236b922c is deliberately revised: the user-accepted safe replacement requires a private checkpoint in addition to the published canonical document.
REQ-DATA-590ff8b1: automatic chunks carry 1-based inclusive source_paragraph_start/end; edited/inserted chunks carry null bounds. Root plan_fingerprint hashes source paragraph semantics and a core policy version; request_fingerprint hashes nonsecret request inputs.
REQ-FUNC-d582b019: resume accepts only verified source-plan prefixes; current profile/prompts/context may change for remaining paragraphs, with a durable warning. Existing strategy/operator instructions remain checkpoint-owned.
REQ-REL-782398af: first-run checkpoints use chunks_text.json; replacement checkpoints use chunking_pending.json while public consumers continue reading completed chunks_text.json. Mode switches discard only uncommitted replacement state.
REQ-REL-0c8588a0: publication stages metadata before moving owned originals into a relative backup. On error restore originals; keep backup on failed restore. No crash-atomicity promise.
Manual selective changes run against a staged owned-artifact snapshot (copy metadata; hardlink immutable audio with copy fallback), so existing selective services cannot partially mutate live files. Publication moves only changed/deleted/new owned files.
REQ-FUNC-978f58f7: edited/inserted prose uses body role, unknown confidence, empty flags and no automatic bounds; unchanged IDs/metadata remain.
### Files and test seams
Core pure modules; chunking_document_service persistence facade; chunking_input_service source adapter; deterministic/AI orchestrators; chunking_ai_service provider adapter; chunking_edit_service manual mutations; chunking_publication_service staging/rollback.
UI controller removes pre-reset and reloads service-published manifest once. Config and reset ownership register pending file. EN/RO guides and Unreleased changelog describe changed behavior.
Focused tests: core structural/coverage cases, service fake-provider budget/resume tests, IO failure injection, stable-ID selective impact, controller confirmation/deferral. No live provider or full suite.
### Risks and open decisions
One project operation at a time is an existing UI constraint. Validate owned paths against root, redirects and source overlap. Staging must not duplicate large audio unnecessarily. Old persisted shapes are deliberately unsupported; no migration.
### Requirement map
REQ-NFR-6df93f95 -> pure imports; REQ-FUNC-6a9a707e -> structural subranges; REQ-DATA-20f1afcf -> materialization metadata; REQ-DATA-590ff8b1 -> source coverage/plan check.
REQ-FUNC-16bd24d0 -> oversized fallback; REQ-NFR-149f8458 -> cost cursor; REQ-REL-782398af -> pending/checkpoint path; REQ-REL-0c8588a0 -> staging publication and rollback.
REQ-FUNC-978f58f7 -> edit service; REQ-FUNC-d582b019 -> request policy warning.
