## Design

- Components: change PDF layout ordering in `text_extraction_adapters.py`; observe downstream column comparison in `cleanup_analysis_service.py` without changing it (REQ-FUNC-6dd114ad, REQ-FUNC-6c977d3b).
- Interface: keep `_order_pdf_lines` inputs, tuple result, layout-mode tokens, warning/reason codes, and `_pdf_line_sort_key` unchanged (REQ-FUNC-6dd114ad, REQ-FUNC-6c977d3b).
- Classification: evaluate the existing left and right predicates once per line and assign exactly one of left, right, or spanning/ambiguous; a line satisfying both becomes spanning rather than contributing to both column populations (REQ-FUNC-6dd114ad).
- Vertical ordering: partition spanning lines once into top, bottom, or ambiguous, with a line satisfying both thresholds assigned conservatively to the ambiguous partition so it cannot be emitted twice (REQ-FUNC-6dd114ad).
- Single-column data: normalize `column = 0` before every single-column return, including short pages and unusable widths, while preserving top-left sorting (REQ-FUNC-6c977d3b).
- Storage: source-ledger schema and geometry keys remain unchanged; corrected ordering only changes duplicated canonical output and inconsistent column values (REQ-FUNC-6dd114ad, REQ-FUNC-6c977d3b).
- Rejected alternative: deduplicating the final ordered list would hide overlapping classifications and still let centered lines falsely establish a two-column layout (REQ-FUNC-6dd114ad).
- Test seams: helper-level `_order_pdf_lines` identity, geometry, modes, reasons, and column assertions cover both requirements; a real PDF through `extract_text` covers canonical output (REQ-FUNC-6dd114ad).
- Expected files: the two focused requirements, this journal, `text_extraction_adapters.py`, `test_text_extraction_service.py`, `.agentic/knowledge/Text_Cleanup.md`, and `CHANGELOG.md`.
