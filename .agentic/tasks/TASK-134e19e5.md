## Design

Components touched: Character Discovery, Voice Profiles and App Shell.

The accepted word range moves from `narrator_definition_service` to
`tts_budget_service.preview_word_bounds()`, and the config constants rename from
`DEFAULT_NARRATOR_PREVIEW_*` to `DEFAULT_VOICE_PREVIEW_*`. `tts_budget_service`
already owns `estimated_word_count`, imports only `config`, and is already
imported by `character_discovery_service`, so no module gains a dependency and no
cycle is possible. `narrator_preview_word_bounds()` and
`preview_text_range_error()` stay where they are as thin delegates, because the
narrator editor and the canonical defaults read them through
`narrator_definition_service` (REQ-FUNC-11743b06, REQ-UX-fb5a66cb).
`DEFAULT_TTS_MIN_PREVIEW_AUDIO_SECONDS` loses its last consumer and is removed.

Character preview text becomes composed rather than quoted, so
`_build_character_preview_text` reduces to normalize, range-check, return - and
four helpers used by nothing else are deleted: `_candidate_preview_text`,
`_preview_text_supported_by_evidence`, `_normalized_preview_support_text` and
`_spoken_preview_fragment`, plus `_minimum_character_preview_word_count`
(REQ-FUNC-cc8611bc). `_evidence_has_direct_dialogue`,
`_text_contains_dialogue_markers` and `_reason_mentions_dialogue` stay: candidate
filtering calls them at lines 1137, 2016, 2127, 2129 and 2888.

No new fallback code. `_synchronized_character_preview_text` already resolves
`discovered_preview_text or localized_preview_text`, and it must stay downstream
because the project voice language is unknown during discovery, so discovery
storing `""` is what triggers the default (REQ-FUNC-11743b06).

Interface changes are additive except the rename: `preview_word_bounds()` on
`tts_budget_service`, and one `character_voices.error_preview_text_out_of_range`
key in `en` and `ro`. No data format changes; `characters.json` and
`characters_voice.json` keep their field sets and `preview_text` stays a string
that may be empty.

Two operator-requested corrections ride along. Narrator generation stops treating
a line break as a refusal reason - two sites only, the substitution reason at
`narrator_profile_generation_service.py:952` and the prompt rule at
`narrator_profile_generation_user.txt:37` (REQ-FUNC-1202a564, REQ-FUNC-05eabf3a).
And `_normalized_character_preview_text` stops returning `""` for text over the
character limit, which silently destroyed an operator's preview on every profile
load; length is now the range check's business, and the normalizer collapses
spaces and tabs while preserving line breaks so both operations agree.

Rejected alternative: adding a second `composed_preview_text` field beside the
quoted one. With quoting gone there is nothing to disambiguate, so `preview_text`
simply changes meaning and the response schema is untouched.

Test seams. REQ-FUNC-cc8611bc and REQ-FUNC-11743b06 attach at
`_build_profile_from_synthesis` in `tests/test_character_discovery_service.py`,
where `test_build_profile_from_synthesis_uses_dialogue_preview_fallback` inverts
into a composed-preview test. The default fallback attaches at `sync_voice_plan`
in `tests/test_character_voices_service.py`. REQ-UX-fb5a66cb attaches at
`handle_save_prompt_requested` in `tests/test_character_voices_ui_controller.py`.
The narrator line-break relaxation attaches at the existing boundary tests in
`tests/test_narrator_profile_generation_service.py`.
