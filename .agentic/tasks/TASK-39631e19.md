## Design

- REQ-FUNC-75d5b274: `handle_cleanup_requested` will branch only on a valid completed Cleanup document, confirm, call `text_cleanup_state_service.reset_cleanup`, replace `window._current_manifest`, then start the normal worker; reset failure stays before start_operation.
- REQ-REL-43c63d8c: running, paused, finalizing, and failed documents will use the existing worker path unchanged, preserving their checkpoint and its service-owned recovery decisions.
- REQ-UX-6fb5efc7: the page will make active editing authoritative for the cleaned editor during same-project state refreshes and gate conflicting signal emitters plus profile controls; the existing controller refresh after failed Save will therefore retain the draft.
- REQ-UX-e1bb52ba: Home New/Open will ask before launching a picker when the page reports a modified draft, and `activate_project` will explicitly discard only after new-project creation or project-open success.
- Test seams: controller stubs capture reset/order/worker manifests; page Qt tests inspect emitted signals and editor state; Home/MainWindow tests simulate dialog decisions, picker cancellation, and actual activation.
- Rejected alternative: storing drafts outside the project or clearing on warning acceptance would broaden scope and loses the required picker-cancel safety.
