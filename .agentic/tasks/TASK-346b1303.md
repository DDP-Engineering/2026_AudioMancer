## Design

Components: Text Cleanup (adjudication + page), AI Runtime (provider client).

**Reservation (REQ-FUNC-644ff463).** `_require_context_budget` becomes
`_resolve_output_reservation`, which returns the reservation instead of only
validating, so one value feeds both the budget decision and the request - the
duplicate constant that let them disagree is gone. It is
`min(profile max_output_tokens, ceiling - estimated_input)` against the existing
70% ceiling and byte//2 input estimator, and it raises the unchanged
`ContextBudgetExceededError` when that falls under the batch's answer floor, so
recursive splitting and single-question fallback keep working untouched. The
answer floor is the worst-case answer document for that batch - every
`question_id` paired with its longest `choice` - counted at one token per UTF-8
byte rather than the input estimator's byte//2: JSON answer text is
punctuation-dense, and a floor that under-counts would send a request that
truncates instead of splitting one that does not fit. Module constant
`MAX_OUTPUT_TOKENS` is deleted; no test or caller reads it.

**Rejected:** raising `MAX_OUTPUT_TOKENS` to a larger fixed number. It keeps a
second hidden limit that silently overrides the operator's own profile setting,
and any fixed value is wrong for either a 16K or a 128K profile.

**Failure record (REQ-NFR-8d83d955).** `chat_json` pre-binds `raw_payload` and
`raw_body` beside the existing `raw_content`, so the failure log record can
carry the response body and `normalize_provider_usage` output under the field
names the success record already uses. A transport failure leaves both unbound
and the record omits them.

**Error text (REQ-FUNC-3875ac3b).** `_extract_message_content` takes the
request's resolved output limit and names it in the length RuntimeError; its two
call sites pass the value from the active payload's `max_tokens` or
`max_completion_tokens`. Still no prompt or response content in the message.

**Page (REQ-UX-b3547171, REQ-UX-860d8bfc).** `_apply_preview_minimum_widths`
sets both preview group boxes to the larger of their two `minimumSizeHint`
widths - reading the hint, never the applied minimum, so repeated calls cannot
ratchet the panes wider. It runs from `showEvent` and `resizeEvent`, as the
Speech Blocks splitter does, because a font-size change restyles the Edit/Save/
Cancel row that makes the right pane wider. Equal opening width is equal stretch
factors plus one `setSizes` of two equal parts on first show; equal stretch then
splits every later width change evenly, so a dragged separator keeps its
position.

**Test seams.** `tests/test_cleanup_adjudication_contract.py` - reservation for a
roomy profile, a clamped profile, and an oversized batch (REQ-FUNC-644ff463).
`tests/test_llm_provider_service.py` - failure record fields for a response
failure and a transport failure (REQ-NFR-8d83d955), and the limit inside the
length error (REQ-FUNC-3875ac3b). `tests/test_text_cleanup_page.py` - equal
minimum widths (REQ-UX-b3547171) and equal shown widths (REQ-UX-860d8bfc).

**Files.** `services/cleanup_ai_adjudication_service.py`,
`services/llm_provider_service.py`, `ui/pages/text_cleanup_page.py`, plus the
