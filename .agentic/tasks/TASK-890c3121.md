## Design

- REQ-FUNC-23c51ea4: Normalize scalar and multipart assistant content in `_extract_message_content`, raising a fixed refusal-specific ValueError only for non-empty refusal strings after output-limit precedence; the test seam is mocked chat responses and captured request counts in `test_llm_provider_service.py`.
- REQ-FUNC-a0ea278d: Extend the shared numeric coercer to finite integral floats and use one field-normalization helper for provider and persisted shapes, deriving only absent/null totals; parameterized `test_token_usage_service.py` cases cover normalization, coercion, merge, restore, and round-trips.
- REQ-FUNC-18168ed4: Move both compatibility decisions to a call-level immediate-adaptation loop whose mutable payload survives outer attempts, using private marker exceptions from the HTTP layer and no persisted capability state; exact request-body and fallback-log sequences are the test seam.
- REQ-FUNC-388c7b18: Add private schedule constants and a monotonic, short-slice wait helper called only after retry classification and before another outer attempt; captured delays plus controlled clock/sleep/cancellation callbacks form the test seam.
- REQ-FUNC-23c51ea4 and REQ-FUNC-18168ed4: Keep the public `chat_json` signature, JSON repair policy, retry-count meaning, transaction schema, structured-output policy, and fixed length-limit failure unchanged.
- REQ-FUNC-a0ea278d: Keep the durable token-usage keys and provider-reported valid totals unchanged; no input or output count is synthesized.
- REQ-FUNC-18168ed4 and REQ-FUNC-388c7b18: Reject persisted backend capability flags and blocking whole-delay sleeps because both would exceed the per-invocation and cancellation contracts.
- Expected implementation and test files are `llm_provider_service.py`, `token_usage_service.py`, `test_llm_provider_service.py`, and `test_token_usage_service.py`; delivery also updates the four linked requirements, two specs, task journal, AI Runtime knowledge page, and changelog.
