## Design

- Components: AI Settings page/controller, backend probe service, settings validation, and AI Runtime documentation.
- REQ-FUNC-8eba808c: the page records the stable ID currently represented by the editor and synchronizes that owner directly before any selected profile is loaded.
- REQ-FUNC-e9d13e10: failed results update only status/message; successful results alone replace profile-local discovery models and model-associated context metadata.
- REQ-FUNC-20817a63: `probe_profile` adds `discovered_context_model_name`; provider helpers obtain optional metadata only for the effective selected model and normalize values to the UI-supported range.
- REQ-FUNC-6f8e52c8: the existing pass-through settings round trip persists the context-owner field, and the page auto-fills only when owner and effective model match and the manual-override flag is false.
- REQ-FUNC-6c33e242: HTTP status retains its dedicated message while read-phase OSError/HTTPException and decode failures return categorized safe failed results.
- Interface: the probe-result dictionary gains one optional model-owner field; the shared JSON reader gains method/body support for Ollama `POST /api/show`.
- Data: profile IDs remain stable; discovery and override fields stay profile-local and are validated through the existing settings round trip.
- Rejected alternative: deriving the outgoing editor owner from `currentRow()` was rejected because Qt has already changed that row when the signal runs and programmatic reloads can redirect writes.
- Test seams: Qt page switching/mutation/probe round trips; mocked `urlopen` request/read responses; controller popup path; settings validation/reload.
- Expected implementation files: `ai_backend_service.py`, `ai_settings_page.py`, and focused tests for the service/page/controller.
