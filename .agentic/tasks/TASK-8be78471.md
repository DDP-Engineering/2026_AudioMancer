## Design

Components touched: Platform Settings UI (configuration, settings validation, TTS
settings page), Speech Blocks and TTS Audio Blocks (budget resolution).

Operator token cap. `resolve_cached_tts_budget` gains an optional maximum, and a
new `resolve_generation_token_limit()` reads it from settings. The effective
budget is the smaller of the operator maximum and whatever the runtime reports,
so the operator can only ever lower it. The cap is applied where the budget is
built, not afterwards, so every derived figure - audio seconds, split seconds and
safe word count - follows from one token number.

Both budget paths take the cap, because Speech Blocks planning and Audio Blocks
generation must agree; a cap on one alone would have Speech Blocks planning
blocks that Audio Blocks then split again.

Regression fix. `_ensure_clone_model_loaded` skipped reloading an already-active
clone model only when the budget happened to come from `runtime_effective`. The
previous task made `range_recommended_maximum` win that race, so the early return
became unreachable and every run reloaded a loaded model. The condition now turns
on the live active-model identity alone, which is what it was always asking.

Rejected alternative: narrowing the budget after resolution, the shape the
retired narration block target used. It leaves the payload briefly describing a
budget that is not the one used, and every consumer must remember to narrow.

Test seams: `tests/test_tts_budget_service.py` for the cap;
`tests/test_audio_blocks_service.py` for the early return.
